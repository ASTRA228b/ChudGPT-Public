# ChudGPT-Public-Music V1 quality update

Generated: 2026-08-27

## Result

Music V1 remains a separate, purely generative 20,999,184-parameter checkpoint. It does not route through Public V20, Pro, an external model, a response table, or fallback song text. The API, website, Discord command, and desktop selector retain isolated Music sessions and report `music: true`.

## Root causes found

- The original 714-conversation corpus did not sufficiently teach vague requests such as `Make music`.
- Public's general chat repair loop limited later candidates to 80 tokens, which is useful for casual chat but truncated songs.
- Complete-song selection rewarded individual section labels too weakly and could select short fragments.
- Title/style decisions were present in history but were not reinforced when the small model handled later follow-ups.
- Recent Discord logs also showed unrelated responses to `you are cool`, `are you sigma`, `Shut`, and repeat requests in standard Public mode.

## Changes

- Complete-song decoding now delays only the model's end-of-sequence token for
  the first 140 generated tokens. This prevents a generated title and style
  from ending the draft before the lyrics begin. The title, style, sections,
  and every lyric token remain model-selected; runtime code inserts no lyrics.
- Title and style metadata are now requested and rewarded only when the user
  asks for them; ordinary song requests prioritize the generated lyrics.
- Full-length minimum decoding is enabled only for explicit full/complete-song
  requests. Ordinary song and fragment requests keep a naturally shorter scope.

- Expanded Music data to **2,798 unique conversations**: 2,518 training and 280 validation.
- Added varied complete songs, vague requests, title/style recall, revisions, genres, moods, and subjects.
- Added a Music-only full-length neural sampling path. It samples six drafts and ranks only model-generated text; it never supplies or rewrites lyrics.
- Music now overrides Public's chat router completely. Exact math, meme, emoji, identity, Discord-context, instruction, reviewed-response, and repair-answer helpers cannot provide Music reply text.
- Removed Music from the 80-token general-chat repair behavior.
- Improved generated-draft scoring for `Title`, `Style`, distinct song sections, adequate length, and continuity with earlier generated choices.
- Added a conversation-state reminder containing the title/style already generated in the current session. Final text is still generated by the checkpoint.
- Added a repeatable checkpoint evaluator in `evaluate_music_v1.py`.
- Added targeted standard-Public corrections derived from recent Discord logs without routing Music through Public's reviewed responder.

## Training

- Architecture: 20,999,184 parameters; 1,024-token model context
- Device: CUDA with automatic mixed precision
- First update: 500 steps, validation loss **1.3039 at step 100 -> 0.7541 at step 500**
- Continuation update: 400 lower-learning-rate steps, final validation loss **0.6448**
- Active local checkpoint: `checkpoints/public_music_v1/best.pt`
- Rollback checkpoint: `checkpoints/archive/public_music_v1_step400_20260827/best.pt`

## Verification

- Public suite: **280 passed**
- Discord bot suite: **83 passed**
- Music corpus: **2,798 records / 2,798 unique**
- Evaluation logs: `reports/music_v1_old_step400_eval.json`, `reports/music_v1_step500_eval_v2.json`, and `reports/music_v1_final_eval.json`

## Honest limitation

The update is measurably better than the original step-400 checkpoint at producing recognizable titles, styles, and sectioned lyrics, but it is still a tiny experimental model. Unseen generations can contain invented words, weak rhymes, repeated sections, incorrect genre choices, or forgotten details. The evaluator preserves those real outputs rather than replacing them with polished canned text.
